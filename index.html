Paradigma Declarativo: UI = f(state) y Virtual DOM

Por qué en React jamás usamos document.getElementById ni mutamos el DOM manualmente.

📌 ¿Qué cambia entre el JS tradicional y React + Vite?

  • •Imperativo (Vanilla DOM): Buscas el nodo en el DOM y le cambias el texto paso a paso. Es propenso a desincronización.
  • •Declarativo (React): Declaras cómo debe verse la interfaz según el estado actual: UI = f(state). Si el estado cambia con una nueva referencia, React re-ejecuta tu función y actualiza solo lo necesario (Reconciliación).
❌ Enfoque Imperativo (Prohibido en React) Evitar en React 
// Manipulación directa del DOM
let stock = 5;
const badge = document.getElementById('stock');

function vender() {
  stock--;
  badge.textContent = stock === 0 ? 'Agotado' : stock;
}
✅ Enfoque Declarativo (React + Vite) Estándar React + Vite 
// Tu componente es una función pura de (props, state)
function TarjetaProducto({ stock }) {
  const agotado = stock === 0;
  return (
    <span className={agotado ? 'bg-red-100' : 'bg-green-100'}>
      {agotado ? 'Agotado' : `Disponible: ${stock}`}
    </span>
  );
}

MÓDULO 1 · MENTALIDAD REACT & OPERADORES JSX SLIDE 3 DE 30

const vs let, Scope de Bloque y Memoria (Stack vs Heap)

Entender por qué const NO congela objetos y cómo React detecta cambios con Object.is().

📌 La regla de oro de la memoria en React

  • •Stack (Primitivos): number, string, boolean se comparan por valor.
  • •Heap (Objetos y Arreglos): La variable en el Stack solo guarda la dirección de memoria (ej. 0x4F2A).
  • •Por qué falla mutar en React: Si haces usuario.rol = "Admin" y luego setUsuario(usuario), React compara Object.is(0x4F2A, 0x4F2A) === true y cancela el re-render.
❌ Mutación de Referencia (React NO renderiza) Evitar en React 
const [aprendiz, setAprendiz] = useState({
  nombre: 'Camila',
  puntos: 80
});

const subirPuntos = () => {
  aprendiz.puntos = 100; // ⚠️ Misma dirección en Heap
  setAprendiz(aprendiz); // Object.is(prev, next) -> true (Se ignora)
};
✅ Nueva Referencia en Heap (React SÍ renderiza) Estándar React + Vite 
const [aprendiz, setAprendiz] = useState({
  nombre: 'Camila',
  puntos: 80
});

const subirPuntos = () => {
  const copia = { ...aprendiz, puntos: 100 }; // Nueva dirección Heap
  setAprendiz(copia); // Object.is(prev, next) -> false (Re-render!)
};

Operadores Críticos para JSX: ?., ?? vs || y Ternario vs &&

Evita pantallas blancas por null/undefined y el famoso bug del número 0 impreso en pantalla.

📌 Los 3 operadores de supervivencia en componentes React

  • •Optional Chaining (?.): Detiene la evaluación si una propiedad es null o undefined antes de que la API responda.
  • •Nullish Coalescing (??) vs OR (||): 0 || 10 devuelve 10 (¡borra el cero!). En cambio, 0 ?? 10 respeta el 0 porque solo reemplaza null o undefined.
  • •La trampa del 0 con && en JSX: En React, {items.length && <Lista />} imprime un "0" literal en el HTML cuando el arreglo está vacío. Usa siempre items.length > 0 ? ... : ....
❌ Bugs Clásicos con || y && en JSX Evitar en React 
// 1. Si descuento es 0%, || lo pisa con 15%
const desc = producto.descuento || 15;

// 2. Si notificaciones es 0, React pinta un "0" en pantalla
return (
  <div>
    {notificaciones && <span>Tienes alertas</span>}
  </div>
);
✅ Código Blindado con ?., ?? y Ternario Estándar React + Vite 
// 1. ?? respeta el 0 y '' válidos
const desc = producto?.descuento ?? 15;
const ciudad = aprendiz?.sede?.ciudad ?? 'Garzón';

// 2. Condición booleana explícita o ternario
return (
  <div>
    {notificaciones > 0 ? <span>Tienes {notificaciones} alertas</span> : null}
  </div>
);

MÓDULO 2 · FUNCIONES FLECHA, CLOSURES Y DESESTRUCTURACIÓN SLIDE 6 DE 30

Arrow Functions y Retorno Implícito de Objetos () => ({})

La sintaxis estándar para definir componentes funcionales, callbacks de eventos y transformaciones.

📌 Por qué los paréntesis () son obligatorios al retornar un objeto

  • •En una función flecha, si escribes x => { id: x }, JavaScript interpreta las llaves {} como el bloque de cuerpo de la función y devuelve undefined.
  • •Al envolver las llaves entre paréntesis x => ({ id: x }), fuerzas a JavaScript a evaluarlo como una expresión de objeto literal.
  • •Lo usarás todos los días en .map(item => ({ ... })) y en callbacks de estado setForm(prev => ({ ...prev, activo: true })).
❌ Error Silencioso: Llaves sin paréntesis Evitar en React 
// JavaScript cree que {} es el cuerpo de la función
const crearOpcion = (id, nombre) => {
  value: id,
  label: nombre
};
// Resultado: undefined
✅ Retorno Implícito Correcto: () => ({}) Estándar React + Vite 
// Los paréntesis envuelven el objeto literal
const crearOpcion = (id, nombre) => ({
  value: id,
  label: nombre
});
// Resultado: { value: 1, label: 'ADSO' }

Closures y Updater Functions en useState: prev => prev + 1

Cómo evitar el bug de Stale State (estado obsoleto) cuando actualizas el estado múltiples veces.

📌 ¿Por qué setCount(count + 1) tres veces seguidas solo suma 1?

  • •En React, las variables de un render son una "fotografía" fija en el tiempo (un closure). Si count vale 0, hacer tres veces setCount(count + 1) ejecuta tres veces setCount(0 + 1).
  • •Cuando pasas una función actualizadora (Updater Function) setCount(prev => prev + 1), React las encola y le entrega a cada función el resultado fresco de la anterior.
❌ Stale Closure: Usa el valor congelado del render Evitar en React 
function Contador() {
  const [likes, setLikes] = useState(0);

  const darTripleLike = () => {
    setLikes(likes + 1); // 0 + 1
    setLikes(likes + 1); // 0 + 1
    setLikes(likes + 1); // 0 + 1 -> ¡Termina en 1!
  };
}
✅ Updater Function: Cola funcional segura Estándar React + Vite 
function Contador() {
  const [likes, setLikes] = useState(0);

  const darTripleLike = () => {
    setLikes(prev => prev + 1); // 0 -> 1
    setLikes(prev => prev + 1); // 1 -> 2
    setLikes(prev => prev + 1); // 2 -> 3 -> ¡Termina en 3!
  };
}

Desestructuración de Objetos: Firma de Props, Alias y Defaults

Cómo reciben parámetros el 100% de los componentes profesionales en React + Vite.

📌 Las 4 técnicas de desestructuración que usarás en cada componente

  • •Extracción directa: function Card({ titulo, precio }) evita repetir props.titulo.
  • •Valores por defecto (=): { rol = "Aprendiz" } se activa solo cuando la propiedad es undefined.
  • •Renombrado con alias (:): { id: codigoFicha } renombra id para evitar colisiones de nombres.
  • •Anidada: { direccion: { ciudad = "Garzón" } = {} } extrae propiedades internas sin romper si el padre no existe.
❌ Repetición verbosa de props.* Evitar en React 
function FichaAprendiz(props) {
  const nombre = props.nombre;
  const rol = props.rol !== undefined ? props.rol : 'Aprendiz';
  const codigo = props.id;
  return <div>{codigo} - {nombre} ({rol})</div>;
}
✅ Desestructuración Limpia en la Firma del Componente Estándar React + Vite 
function FichaAprendiz({
  id: codigo,
  nombre,
  rol = 'Aprendiz',
  sede: { municipio = 'Garzón' } = {}
}) {
  return <div>{codigo} - {nombre} ({rol} · {municipio})</div>;
}

Desestructuración de Arreglos y Rest Operator (...rest)

Por qué useState retorna un arreglo [state, setState] y cómo reenviar props en React.

📌 Arreglos (por posición) vs Objetos (por clave)

  • •¿Por qué useState devuelve un arreglo [valor, setValor]? Porque en un arreglo puedes ponerle el nombre que quieras a las variables según su posición: const [filtro, setFiltro] = useState("").
  • •Operador Rest (...rest): Agrupa el resto de elementos o propiedades en una nueva estructura. En React es vital para crear componentes envoltorio: function Boton({ variante, ...atributosHTML }).
❌ Acceso manual por índices [0] y [1] Evitar en React 
const estadoModal = useState(false);
const abierto = estadoModal[0];
const setAbierto = estadoModal[1];
✅ Desestructuración Posicional + Rest Operator Estándar React + Vite 
// 1. Desestructuración posicional en Hooks
const [abierto, setAbierto] = useState(false);

// 2. Separar props propias de atributos nativos del DOM
function InputSena({ label, error, ...inputProps }) {
  return (
    <label>
      {label}
      <input className="border p-2" {...inputProps} />
    </label>
  );
}

MÓDULO 3 · INMUTABILIDAD Y PATRONES DE ESTADO CON SPREAD SLIDE 11 DE 30

Spread Operator en Objetos (...): Clonación Superficial y Formularios

Cómo actualizar un campo dinámico [name]: value sin borrar el resto del formulario.

📌 El orden de las propiedades en {...original, ...cambios}

  • •En un objeto literal, si una propiedad se repite, gana la última escrita a la derecha.
  • •Por eso en React siempre ponemos { ...formulario, [e.target.name]: e.target.value }: primero volcamos todas las propiedades anteriores y luego sobrescribimos la propiedad modificada usando Computed Property Names [campo].
❌ Error: Sobrescribir todo el objeto en useState Evitar en React 
const [form, setForm] = useState({ nombre: 'Juan', correo: 'j@sena.edu.co' });

// ⚠️ ¡Peligro! Esto borra la propiedad "correo"
const cambiarNombre = (nuevoNombre) => {
  setForm({ nombre: nuevoNombre });
};
✅ Patrón Universal de Formularios en React Estándar React + Vite 
const [form, setForm] = useState({ nombre: 'Juan', correo: 'j@sena.edu.co' });

const handleChange = (campo, valor) => {
  setForm(prev => ({
    ...prev,
    [campo]: valor // Propiedad computada dinámica
  }));
};

MÓDULO 3 · INMUTABILIDAD Y PATRONES DE ESTADO CON SPREAD SLIDE 12 DE 30

Trampa del Shallow Copy vs Deep Spread en Objetos Anidados

Por qué {...obj} solo copia el primer nivel y cómo clonar sub-objetos correctamente.

📌 Cuidado con los objetos dentro de objetos

  • •El operador spread { ...usuario } hace una copia superficial (Shallow Copy): los objetos internos como usuario.preferencias siguen apuntando a la misma dirección de memoria del objeto original.
  • •Para actualizar una propiedad anidada en React, debes hacer spread en cada nivel de la ruta modificada o usar structuredClone(estado).
❌ Trampa Shallow Copy: Mutar el objeto hijo Evitar en React 
const copia = { ...usuario };
// ⚠️ ¡Sigue mutando al usuario original porque "direccion"
// comparte la misma referencia en el Heap!
copia.direccion.ciudad = 'Neiva';
✅ Deep Spread Nivel por Nivel Estándar React + Vite 
const usuarioActualizado = {
  ...usuario,
  direccion: {
    ...usuario.direccion,
    ciudad: 'Neiva'
  }
};
// usuario.direccion !== usuarioActualizado.direccion (100% seguro)

Operaciones Inmutables en Arreglos: Prohibido .push() y .splice()

Tabla de equivalencias entre métodos mutables prohibidos y patrones inmutables para React.

📌 Métodos que MUTAN (❌ Prohibidos en estado) vs Métodos que CLONAN (✅ React)

  • •Agregar al final: En vez de arr.push(x) ➔ usa [...arr, x].
  • •Agregar al inicio: En vez de arr.unshift(x) ➔ usa [x, ...arr].
  • •Eliminar elementos: En vez de arr.splice(i, 1) ➔ usa arr.filter(item => item.id !== id).
  • •Insertar en posición i: Usa [...arr.slice(0, i), nuevo, ...arr.slice(i)].
❌ Mutación con .push() en estado de React Evitar en React 
const [tareas, setTareas] = useState(['Instalar Vite']);

const agregar = (nueva) => {
  tareas.push(nueva); // ⚠️ Muta el mismo arreglo en memoria
  setTareas(tareas);  // React ve la misma referencia y NO repinta
};
✅ Inserción Inmutable con [...tareas, nueva] Estándar React + Vite 
const [tareas, setTareas] = useState(['Instalar Vite']);

const agregar = (nueva) => {
  setTareas(prev => [...prev, nueva]); // Nuevo arreglo en memoria
};

Patrón CRUD Inmutable Completo para Carritos y Listas en React

Cómo combinar .map(), .filter(), .some() y Spread para gestionar colecciones de objetos.

📌 La receta definitiva para actualizar o alternar un elemento por ID

  • •Actualizar un ítem por ID: lista.map(item => item.id === id ? { ...item, ...cambios } : item).
  • •Upsert (Incrementar si existe o agregar si es nuevo): Verifica primero con lista.some(item => item.id === nuevo.id); si existe usa .map(), y si no existe retorna [...lista, nuevo].
❌ Buscar con .find() y mutar el objeto encontrado Evitar en React 
const toggleTarea = (id) => {
  const tarea = tareas.find(t => t.id === id);
  tarea.completada = !tarea.completada; // ⚠️ Muta el objeto interno
  setTareas([...tareas]); // Mala práctica: ya contaminaste el estado previo
};

function carritoReducer(state, action) {
  switch (action.type) {
    case 'AGREGAR':

    case 'VACIAR':
      return { ...state, items: [] };
    default:
      return state;
  }
}

El Event Loop de JavaScript: Call Stack, Microtasks y Macrotasks

Por qué las Promesas (.then / await) siempre se ejecutan antes que un setTimeout(..., 0).

📌 El orden de prioridad exacto del motor JavaScript

  • •1. Call Stack (Síncrono): Todo el código normal se ejecuta línea por línea primero.
  • •2. Microtask Queue (Alta Prioridad): Apenas se vacía el Call Stack, el Event Loop ejecuta TODAS las resoluciones de Promesas (.then, await, queueMicrotask).
  • •3. Macrotask Queue (Baja Prioridad): Recién cuando la cola de Microtasks queda vacía, se ejecutan los temporizadores (setTimeout, setInterval) y eventos de I/O.

Concurrencia en Dashboards: Promise.all vs Promise.allSettled

Elimina el cuello de botella secuencial (Waterfall) al cargar múltiples endpoints en React.

📌 ¿Cuándo usar Promise.all() y cuándo Promise.allSettled()?

  • •Problema Waterfall: Hacer tres await fetch() en líneas separadas suma sus tiempos ($500\text{ms} + 500\text{ms} + 500\text{ms} = 1500\text{ms}$).
  • •Promise.all([p1, p2, p3]): Lanza todas en paralelo ($500\text{ms}$ total). Si una sola falla, todo el Promise.all se rechaza (Todo o Nada).
  • •Promise.allSettled([p1, p2, p3]): Espera a todas sin importar si alguna falla. Entrega objetos { status: "fulfilled", value } o { status: "rejected", reason }. Ideal para widgets independientes.

Por qué el callback de useEffect NO puede ser async directamente y cómo limpiar peticiones.

  • •1. Nunca escribas useEffect(async () => ...): Una función async devuelve una Promesa, pero useEffect espera que retornes undefined o una función de limpieza (cleanup). Declara una función async interna y llámala.

useEffect(() => {
  const controller = new AbortController();

  async function cargarDatos() {

      const res = await fetch(`/api/ficha/${id}`, { signal: controller.signal });
      if (!res.ok) throw new Error('Error de red');
      setDatos(await res.json());

      if (err.name !== 'AbortError') setError(err.message);
    }
  }

  return () => controller.abort(); // Cleanup al desmontar o cambiar [id]
